# AT Grafana 0.1.0 — Release notes & acceptance record

**Date:** 2026-07-29
**Status:** V1 feature-complete (Phases 0–8 of the [implementation plan](../plans/2026-07-29-at-grafana-v1-implementation-plan.md)); **not yet verified against a live Grafana instance or a real MCP client** — see "Pending manual verification" below.

This document is the canonical acceptance record for the first release. It scores the project against the 10 Definition-of-Done items in [`docs/requirements.md` §7](../requirements.md#7-验收标准definition-of-done-方向), citing the specific automated test(s) backing each claim, and is explicit about what still needs a human with a real Grafana instance and a real MCP client to close out. Nothing below is marked "done" unless it traces to a passing automated test in this repo or a directly-inspectable code property; everything else is marked **Pending manual verification** with a concrete one-line description of what a human needs to do.

## Residual risks (consolidated from Phases 2–6 status notes)

These are carried forward from prior phases' own status notes rather than re-litigated here; a future maintainer should treat this list as the single place to check before deeper reliance on the affected code paths:

1. **`getAlertRuleHistory` response shape is unverified** (flagged since Task 2.1 / Phase 2). It uses `/api/v1/rules/history?ruleUID=`, chosen with low confidence and never validated against a real Grafana instance's actual response. `grafana_get_alert_history` passes this through unmodified (Phase 5 status note) — if the real shape differs from what the client's parser expects, this tool may throw `invalid-response` or return a badly-shaped result against a live instance.
2. **The embed proxy's HTML/JS/CSS rewriting is regex-based, not a real HTML/JS parser** (flagged since Task 4.1 / Phase 4, called out in the plan's own Risks table as the single highest-risk item in the whole project). It has only been exercised against hand-written fixture responses in `test/webview/GrafanaEmbedProxy.test.ts`, never a real Grafana build's actual served markup/bundles across Grafana versions. This is the most likely place for the dashboard/alert Webview experience to break in practice.
3. **The dashboard/alert URL scheme the proxy constructs (`buildAlertRuleUrl`, dashboard `/d/:uid` paths, etc.) is unverified against a real Grafana instance** — built from the Grafana docs/API shape, not confirmed by loading a real page.
4. **`grafana_query_datasource`'s cap values are proposed, not calibrated** (Task 6.1 / Phase 6): `maxRangeMs` default 12h, `maxResponseBytes` default 5 MiB. Both are documented as "pending calibration against a real Prometheus/Loki instance" directly in `package.json`'s setting descriptions and `src/grafana/QueryLimits.ts`'s doc comments — they are reasonable guesses, not measured values.
5. (Carried from Phase 6 checkpoint, not previously numbered as a "risk" but equivalent in effect) **No WebSocket/Grafana Live proxying** — real-time panel auto-refresh via Grafana Live will not work through the embed proxy; dashboards will load and can be manually refreshed, but won't push live updates. Documented as an accepted V1 limitation, not a defect to fix before release.

None of these block packaging or the automated test suite — they are all scoped to "needs a live Grafana/Prometheus/Loki instance to confirm or calibrate," which is exactly what Definition-of-Done items 1–3, 6 (partial), 7 (cap calibration), 9, and 10 (partial) above are pending on.

## What's new in 0.1.0

First release. Full V1 feature set per [`docs/requirements.md`](../requirements.md):

- Multi-instance Grafana configuration with Service Account Token auth (SecretStorage-backed) and TLS Trust-On-First-Use
- Dashboard and alert-rule tree views in the sidebar (folder-grouped, filterable, Firing-sorted)
- Native dashboard/alert Webview panels via a local `127.0.0.1` reverse proxy that injects the `Authorization` header server-side (never exposed to the Webview/network front end)
- A 9-tool `at.grafana` MCP catalog (7 management + 2 monitoring-data tools), all `risk: read`, gated by a per-instance "allow Agent background access" toggle, integrated with the shared AT Series MCP Hub (Protocol v1)
- `skills/at-grafana-mcp/SKILL.md` and bilingual (EN/中文) feature and usage docs

See [`docs/plans/2026-07-29-at-grafana-v1-implementation-plan.md`](../plans/2026-07-29-at-grafana-v1-implementation-plan.md) for the full phase-by-phase implementation history.
