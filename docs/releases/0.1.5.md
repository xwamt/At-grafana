# AT Grafana 0.1.5 Release Notes

**Release date:** 2026-11-23
**Baseline:** `0.1.4`

Version 0.1.5 is a reliability, read-only safety, and day-2 operations release. It closes five P0/P1 defects found in the 2026-11-20 source audit, completes the core alert/dashboard UX work, and fixes live compatibility with Grafana 13's default alert state-history backend.

## Highlights

### 1. Prometheus / Loki timestamp normalization (P0)
- `grafana_query_prometheus`, `grafana_query_loki`, and the discovery tools now normalize `epoch milliseconds` (`1700000000000`) to Unix seconds before sending upstream, so Prometheus no longer rejects them and Loki no longer interprets them as nanoseconds near 1970.
- Relative expressions such as `now`, `now-1h`, and `now-30m` are resolved against a single request-time clock and participate in the configured 12-hour range cap.
- RFC3339, Unix seconds, and Loki nanosecond values are preserved as-is; `clampQueryTimeRange` keeps its documented format-preserving contract.

### 2. Test Connection correctness (P0)
- Editing an existing instance and clicking **Test Connection** with a blank token field now falls back to the token stored in `SecretStorage` instead of testing with an empty token.
- `/api/health` is often unauthenticated; the connection test now follows it with a minimal authenticated `/api/search?limit=1` probe, so an invalid or under-privileged Service Account Token is reported as an auth failure rather than a false success.
- Base URLs with a reverse-proxy subpath (`https://host/grafana`) now probe `https://host/grafana/api/health` instead of `/api/health`.

### 3. TLS TOFU concurrency and timeout behavior (P1)
- Concurrent HTTPS requests against an untrusted instance now share one in-flight fingerprint confirmation per `trustStore` + fingerprint, so a single tree expansion no longer opens 2–4 identical modal dialogs.
- When an interactive certificate confirmation is pending, the request's 15-second socket timeout is not started until the user confirms; a slow decision no longer destroys the socket or triggers a retry loop. The timeout still applies normally once the request is sent.

### 4. Embedded proxy read-only hardening and deployment compatibility (P1)
- The embed proxy now rejects `PUT`, `DELETE`, `PATCH`, and all non-query `POST` requests with `403` before opening an upstream connection. The allowlist is validated against the normalized target path, so traversal variants such as `POST /api/ds/query/../../dashboards/db` cannot bypass it.
- Reverse-proxy subpath deployments (`https://ops.internal/grafana`) now preserve the configured prefix in `buildTargetUrl`, rewrite absolute references without duplicating or dropping `/grafana`, and rewrite path-only `Location` redirects onto the proxy prefix.
- Embedded documents now support `gzip`, `br`, and `deflate` upstream responses, and a 401/403 HTML document response renders an actionable "update the Service Account Token" page instead of Grafana's unusable login loop.

### 5. Agent and sidebar UX completeness (P2)
- `grafana_generate_deeplink` now supports `openInIde: true` for `kind: "alertRule"`, opening the existing `AlertDetailPanel` while retaining the non-interactive TLS gate (`openedInIde: false` with a message when the fingerprint is not already trusted).
- `grafana_list_dashboards` and `grafana_list_folders` accept optional `limit` (max 1000) and `page`; full-page results return `{ dashboards/folders, truncated, message }` while ordinary small-instance calls remain backward-compatible bare arrays.
- The Alerts tree supports title and multi-select state filters, including a dedicated **Paused** filter (`rule.isPaused === true`), while the firing badge remains the full unfiltered count. Refreshing or editing one instance now invalidates only that instance's tree and proxy caches.
- `grafana_get_alert_history` supports both Grafana state-history backends: the Loki frame shape (`time`/`line`/`labels`) and the annotation frame shape (`time`/`text`/`prev`/`next`/`data`).

### 6. Grafana 13 alert-history compatibility (live-verified)
- Verified against a live Grafana **13.0.1+security-01** instance using the default `[unified_alerting.state_history] backend = annotations`.
- The annotation backend returns `time`/`text`/`prev`/`next`/`data`, not the previously assumed `time`/`current`/`labels` shape; the parser now handles both.
- Grafana 13's annotation backend serializes annotation `epoch` milliseconds through `time.Unix(..., 0)` (seconds), so response timestamps are 1000× too large. The client normalizes these back to epoch milliseconds.
- The annotation backend ignores the request `limit`; the client now applies the requested limit after parsing.

### 7. Engineering, CI, and documentation
- CI is now single-repository (`npm ci` → typecheck → test → package → VSIX content assertions → audit → upload artifact); the obsolete `at-series-mcp-hub` checkout/build steps were removed.
- Added `test-fixtures/rules-history-dataframe.json` plus parser regression coverage for the annotation-backend shape.
- `skills/at-grafana-mcp/SKILL.md` now includes an SRE incident playbook and Tempo/Elasticsearch `grafana_query_datasource` recipes.
- README, Chinese README, feature docs, and release docs were synchronized with the 0.1.5 behavior.

## Notes and known limitations

- All tools remain `risk: read`; no Grafana or datasource write operations were added.
- Grafana Live / WebSocket push through the embed proxy remains unsupported.
- The UI-level live smoke checklist (DoD 1 / 2 / 3 / 9 in `docs/releases/0.1.0.md`) still requires a human in an Extension Development Host; API-level and MCP-bridge checks were completed on the live Grafana instance above.
