# AT Grafana 0.1.3 Release Notes

Version 0.1.3 aligns the AT Grafana MCP catalog with grafana/mcp-grafana read-only workflows without copying the official 50-tool dump, write APIs, or PromQL/LogQL tutorials. The live catalog grows from 9 tools (0.1.2) to **17 tools**, all `risk: read`.

## Highlights & New Features

### 1. Typed Prometheus and Loki queries (P0)
- **`grafana_query_prometheus` / `grafana_query_loki`**: PromQL and LogQL go through Grafana's datasource proxy (`api/v1/query` / `query_range`, Loki range/instant). They reuse the existing `queryDatasource` metering (rate limit, range/size caps, path confinement).
- **`grafana_query_datasource`** remains the `GET`/`POST` escape hatch for other datasources and unusual paths.
- **Default range window**: if a recognized range endpoint is called with both `start` and `end` omitted, the plugin fills `end=now` and `start=now-maxRangeMs` without wrapping every expr-only range in a truncation envelope.

### 2. Smaller dashboard and search payloads (P0)
- **`grafana_get_dashboard`** defaults to `fields: "targets"` (panel expr + datasource only). Pass `fields: "full"` for the complete model; `summary` stays available for panel inventory.
- **`grafana_list_dashboards`** accepts optional `query` / `tag` / `folderUid` (mapped to Grafana `/api/search` `folderUIDs`).

### 3. Prom/Loki metric and label discovery (P1)
- **`grafana_list_prometheus_metric_names`**: `GET api/v1/label/__name__/values`, optional JS `regex`, cap 200 (`truncated: true` when truncated).
- **`grafana_list_prometheus_label_values`**: `GET api/v1/label/<label>/values`; `label` must match `^[a-zA-Z_][a-zA-Z0-9_]*$`; optional `matcher` → Grafana `match[]`.
- **`grafana_list_loki_label_names` / `grafana_list_loki_label_values`**: Loki label APIs on the same proxy pipeline.
- Invalid regex is a `VALIDATION_ERROR`. Size-cap envelopes from `queryDatasource` are returned as-is.

### 4. Annotations, deeplink, and alert state filters (P1)
- **`grafana_list_annotations`**: read-only `GET /api/annotations` with optional `from`/`to` (epoch ms), `dashboardUid` → Grafana `dashboardUID`, single `tag`, `limit` default/max 100.
- **`grafana_generate_deeplink`**: always returns a Grafana URL (`dashboard` or `explore`). `openInIde` defaults to false; `true` is dashboard-only and calls `atGrafana.openDashboard`. Explore is URL-only. A missing or failing opener still returns `grafanaUrl` with `openedInIde: false`.
- **`grafana_list_alert_rules`**: optional `states` (`firing` / `pending` / `normal` / `unknown`, OR across the array) after the same `normalizeAlertState` correlation as the sidebar. Omit `states` to list every rule. Grafana `inactive` maps to `normal`.

### 5. Agent skill and docs
- Skill `at-grafana-mcp` now points at typed discovery → query, annotations/deeplink, and `states` filters. PromQL/LogQL language docs stay in official grafana/skills (see `references/compose-grafana-skills.md`).
- README / features / usage (EN + zh-CN) document the 17-tool catalog. Historical 9-tool / 11-tool claims in `docs/releases/0.1.0.md` are unchanged.

## Not in 0.1.3

- Write tools (`create_annotation`, dashboard/alert mutation, silence/pause)
- Official metric-metadata / Prom label-*names* / annotation-tags tools
- Opening Explore or alert detail in the IDE Webview
- Tempo / OnCall / Sift / IRM
